# Capítulo III: Requirements Specification

## 3.1 User Stories

The following requirements are written in English and follow the professor’s requested structure. Each story includes a role, goal, benefit, and Given-When-Then acceptance criteria. They remain subject to refinement after interviews and prototype tests.

| Epic/Story ID | Título | Descripción | Criterios de Aceptación | Relacionado con (Epic ID) |
|---|---|---|---|---|
| US01 | Browse the Public Website | As a Visitor, I want to browse AgroLeak’s public website so that I can understand how the product protects irrigation and monitors a target pest. | **Scenario: View the value proposition**<br><br>Given the Visitor opens the landing page,<br>When the page finishes loading,<br>Then it explains the two monitored risks, the IoT process, the safety approach, and the main benefits.<br><br>**Scenario: Browse on a mobile device**<br><br>Given the Visitor uses a mobile device,<br>When the Visitor navigates through the page,<br>Then the content remains readable and usable without horizontal scrolling. | EP01 |
| US02 | Request a Product Demonstration | As a Visitor, I want to submit my contact information so that I can request an AgroLeak demonstration or pilot conversation. | **Scenario: Submit a valid request**<br><br>Given the Visitor completes all required fields with valid information,<br>When the Visitor submits the form,<br>Then the request is registered and a confirmation message is displayed.<br><br>**Scenario: Submit an incomplete request**<br><br>Given one or more required fields are empty,<br>When the Visitor submits the form,<br>Then the page identifies the missing fields and does not register the request. | EP01 |
| US03 | Sign In to the Platform | As a Registered User, I want to sign in securely so that I can access the farms and devices assigned to my account. | **Scenario: Successful sign-in**<br><br>Given the Registered User has valid credentials,<br>When the user submits the sign-in form,<br>Then the platform creates an authorized session and displays the dashboard.<br><br>**Scenario: Invalid sign-in attempt**<br><br>Given the credentials are invalid,<br>When the user submits the form,<br>Then the platform rejects the request without revealing which credential is incorrect. | EP02 |
| US04 | Register a Farm and Plot | As an Agricultural Producer, I want to register my farm and plots so that I can organize every monitored location. | **Scenario: Register valid data**<br><br>Given the Agricultural Producer is signed in and provides the required data,<br>When the registration is confirmed,<br>Then the farm and plot are stored and associated with the producer.<br><br>**Scenario: Register a duplicate plot name**<br><br>Given a plot with the same name already exists in the farm,<br>When the producer submits the duplicate,<br>Then the platform rejects it and requests a different name. | EP03 |
| US05 | Configure an Irrigation Segment | As an Agricultural Producer, I want to assign inlet and outlet sensors and a shutoff valve to an irrigation segment so that AgroLeak can monitor and protect it. | **Scenario: Assign distinct devices**<br><br>Given two available flow sensors and one valve are registered,<br>When the producer assigns them to their roles,<br>Then the segment is saved and marked as ready for calibration.<br><br>**Scenario: Reuse the same flow sensor**<br><br>Given the same sensor is selected as inlet and outlet,<br>When the producer submits the configuration,<br>Then the platform rejects it and explains that two distinct sensors are required. | EP03 |
| US06 | Configure a Flow Anomaly Rule | As an Agricultural Producer, I want to configure a percentage threshold and persistence duration so that anomaly detection reflects the calibrated segment. | **Scenario: Save valid parameters**<br><br>Given the segment has been calibrated,<br>When the producer enters values within the allowed ranges,<br>Then the platform versions and activates the new rule.<br><br>**Scenario: Enter an invalid parameter**<br><br>Given the producer enters a negative threshold or duration,<br>When the rule is submitted,<br>Then the platform rejects it and keeps the previous active rule. | EP03 |
| US07 | View Current Irrigation Status | As an Agricultural Producer, I want to view inlet flow, outlet flow, difference, and valve status so that I can understand the segment’s current condition. | **Scenario: View recent readings**<br><br>Given recent synchronized measurements exist,<br>When the producer opens the segment,<br>Then the platform displays values, unit, percentage, timestamp, quality, and valve status.<br><br>**Scenario: View stale data**<br><br>Given the latest reading is older than the freshness limit,<br>When the producer opens the segment,<br>Then the platform marks the data as outdated and displays the last successful time. | EP04 |
| US08 | Detect a Persistent Flow Anomaly | As an Agricultural Producer, I want AgroLeak to detect a persistent flow difference so that a possible incident is handled before more water is lost. | **Scenario: Difference remains above the rule**<br><br>Given the percentage difference is above the configured threshold,<br>When it remains above the threshold for the persistence duration,<br>Then the platform records a FlowAnomalyConfirmed event with the supporting readings.<br><br>**Scenario: Difference is temporary**<br><br>Given the percentage briefly exceeds the threshold,<br>When it returns to range before the persistence duration,<br>Then the platform does not confirm an anomaly. | EP04 |
| US09 | Close the Shutoff Valve Safely | As an Agricultural Producer, I want the shutoff valve to close after a confirmed anomaly so that the segment enters a safer state until it is inspected. | **Scenario: Close an enabled valve**<br><br>Given a flow anomaly is confirmed and automatic closure is enabled,<br>When the Edge controller receives the closure request,<br>Then it closes the valve, verifies feedback, records the action, and raises an alert.<br><br>**Scenario: Valve feedback does not confirm closure**<br><br>Given a closure command was issued,<br>When feedback is not received within the timeout,<br>Then the system marks the action as failed, activates the local warning, and raises a critical alert. | EP04 |
| US10 | Reopen a Valve after Inspection | As an Agricultural Producer, I want to reopen a closed valve only after recording an inspection so that irrigation does not resume without accountability. | **Scenario: Reopen after a valid inspection**<br><br>Given the anomaly is no longer active and an inspection result was recorded,<br>When an authorized producer confirms reopening,<br>Then the system opens the valve and stores the user, timestamp, and reason.<br><br>**Scenario: Attempt reopening while the anomaly persists**<br><br>Given the anomaly condition is still active,<br>When the producer requests reopening,<br>Then the platform blocks the command and explains the unresolved condition. | EP04 |
| US11 | Configure a Pest Observation Point | As an Agricultural Producer, I want to assign a camera, target pest, and confirmation rule to an observation point so that visual monitoring has an explicit scope. | **Scenario: Save a valid observation point**<br><br>Given a camera, plot, supported target pest, and valid rule are available,<br>When the producer confirms the setup,<br>Then the point is saved with its capture schedule and model version.<br><br>**Scenario: Select an unsupported target pest**<br><br>Given the selected pest is not supported by the active model,<br>When the configuration is submitted,<br>Then the platform rejects it and lists the supported class. | EP05 |
| US12 | Review an AI Pest Detection | As an Agricultural Producer, I want to review the annotated image, predicted class, confidence, and count so that I can evaluate the detection evidence. | **Scenario: Display a completed inference**<br><br>Given the Edge gateway completed an inference,<br>When the producer opens the observation,<br>Then the platform displays the original or annotated image, class, confidence, count, timestamp, and model version.<br><br>**Scenario: Display an uncertain observation**<br><br>Given confidence is below the configured threshold,<br>When the producer opens the observation,<br>Then the platform labels it as uncertain and does not present it as a confirmed pest. | EP05 |
| US13 | Confirm a Target Pest | As an Agricultural Producer, I want AgroLeak to confirm the target pest only when the complete rule is met so that isolated or uncertain images do not trigger an action. | **Scenario: Meet class, confidence, and repetition conditions**<br><br>Given target-pest detections exceed the confidence threshold,<br>When the required number occurs within the configured window,<br>Then the platform records a TargetPestConfirmed event and creates an alert.<br><br>**Scenario: Detect a non-target insect**<br><br>Given the model classifies an observation as NON_TARGET_INSECT,<br>When the inference is processed,<br>Then the evidence is stored but no pest confirmation or control request is created. | EP05 |
| US14 | Authorize a Localized Control Action | As an Agricultural Producer, I want to approve or reject a localized control request so that I remain responsible for the intervention. | **Scenario: Approve a valid request**<br><br>Given a target pest is confirmed and all safety checks pass,<br>When an authorized producer approves the request before it expires,<br>Then the platform sends a signed, time-limited actuation command to the Edge controller.<br><br>**Scenario: Reject or ignore a request**<br><br>Given a control request is pending,<br>When the producer rejects it or its approval window expires,<br>Then no actuator command is sent and the decision is recorded. | EP05 |
| US15 | Execute a Localized Control Action | As an Agricultural Producer, I want AgroLeak to execute a bounded localized action so that the prototype responds physically without exceeding safety limits. | **Scenario: Execute within limits**<br><br>Given a valid command reaches an enabled actuator with no lockout,<br>When the Edge controller validates duration and daily count,<br>Then it activates the mechanism for the authorized duration and records start, stop, and result.<br><br>**Scenario: A safety condition fails**<br><br>Given the actuator is disabled, locked out, or at its daily limit,<br>When an actuation command arrives,<br>Then the controller rejects it, keeps the actuator off, and raises a safety alert. | EP05 |
| US16 | Validate or Correct a Pest Detection | As an Agricultural Producer, I want to mark an observation as correct, incorrect, or uncertain so that the team can analyze model errors without silently changing historical evidence. | **Scenario: Submit a validation label**<br><br>Given the producer can view an observation,<br>When the producer selects a validation label and optional comment,<br>Then the platform stores the annotation separately from the original inference.<br><br>**Scenario: Edit a previous validation**<br><br>Given a validation already exists,<br>When an authorized user changes it,<br>Then the platform versions the change and preserves the audit trail. | EP05 |
| US17 | Manage Alerts and Resolution | As an Agricultural Producer, I want to acknowledge and resolve irrigation and pest alerts so that every incident has a traceable outcome. | **Scenario: Acknowledge an open alert**<br><br>Given an alert is open,<br>When the producer acknowledges it,<br>Then the platform records the user and acknowledgment time.<br><br>**Scenario: Resolve an alert**<br><br>Given the producer completed the required action,<br>When the producer records the result and closes the alert,<br>Then the platform stores the resolution, user, and closing time. | EP06 |
| US18 | Browse Monitoring and Actuation History | As an Agricultural Producer, I want to filter readings, detections, alerts, and actions so that I can reconstruct what happened in a selected period. | **Scenario: Apply valid filters**<br><br>Given historical records exist,<br>When the producer selects a date range, plot, and event type,<br>Then the platform returns matching records in chronological order.<br><br>**Scenario: No records match**<br><br>Given no records match the selected criteria,<br>When the filters are applied,<br>Then the platform displays an empty result without clearing the filters. | EP07 |
| US19 | View Quantitative Summaries | As an Agricultural Producer, I want to view hydraulic and pest-monitoring summaries so that I can understand the selected period. | **Scenario: Generate a summary**<br><br>Given valid synchronized data exists,<br>When the producer opens analytics for a period,<br>Then the platform displays flow statistics, anomaly count, target-pest detections, false-positive labels, and actions.<br><br>**Scenario: Exclude invalid data**<br><br>Given some readings or inferences are invalid,<br>When the summary is calculated,<br>Then the platform excludes them and identifies the excluded record count. | EP07 |
| US20 | View Weather Context | As an Agricultural Producer, I want to view basic weather information so that I can use it as complementary context when reviewing the plot. | **Scenario: Weather service is available**<br><br>Given the plot has valid coordinates and the provider is available,<br>When the producer opens the plot overview,<br>Then the platform displays the selected weather variables and provider timestamp.<br><br>**Scenario: Weather service is unavailable**<br><br>Given the provider cannot be reached,<br>When the overview loads,<br>Then the platform labels the weather data as unavailable without blocking AgroLeak monitoring. | EP07 |
| US21 | Export Operational and Monitoring Reports | As an Agricultural Producer, I want to export raw and aggregated monitoring records so that I can perform offline analysis or submit compliance evidence. | **Scenario: Export data within a valid date range**<br><br>Given the producer selects a valid date range, plot, and format (CSV/PDF),<br>When the export request is confirmed,<br>Then the platform generates a downloadable file containing the filtered telemetry, detections, and action logs.<br><br>**Scenario: Export request with no matching records**<br><br>Given no data exists for the selected criteria,<br>When the producer attempts to export,<br>Then the platform notifies the user and prevents the creation of an empty export file. | EP07 |
| US22 | Manage Multi-User Access and Role Permissions | As an Agricultural Producer, I want to invite team members and assign specific roles so that field operators and advisors have appropriate platform access. | **Scenario: Assign an operator role**<br><br>Given the producer invites a new user with the "Field Operator" role,<br>When the user accepts the invitation,<br>Then the user can view status and acknowledge alerts but cannot modify safety rules or delete plots.<br><br>**Scenario: Revoke user access**<br><br>Given a user has active access to a farm,<br>When the producer revokes their membership,<br>Then the user's active session is terminated and subsequent requests to that farm are blocked. | EP02 |
| US23 | Manage Device Calibration and Maintenance Logs | As an Agricultural Producer, I want to record sensor calibration and physical maintenance events so that data drift and hardware servicing are properly documented. | **Scenario: Log a successful calibration**<br><br>Given a flow sensor or camera requires recalibration,<br>When the producer submits the calibration offset and technician notes,<br>Then the platform stores the maintenance log and updates the device's operational status.<br><br>**Scenario: Flag a malfunctioning device**<br><br>Given a device consistently fails hardware checks,<br>When the producer marks the device as "Under Maintenance",<br>Then the platform suspends automated anomaly rules for its associated segment and raises an informational status. | EP03 |
| US24 | Configure Custom Notification Channels | As an Agricultural Producer, I want to set up push notifications, SMS, or email alerts so that critical incidents reach me immediately when I am away from the platform. | **Scenario: Receive a high-priority alert via SMS/Push**<br><br>Given a critical alert (e.g., confirmed leak or valve failure) is raised,<br>When the notification service triggers,<br>Then an instant message is dispatched to the configured phone number or mobile app within the target latency window.<br><br>**Scenario: Mute notifications during scheduled maintenance**<br><br>Given a maintenance window is active for a plot,<br>When an anomaly event occurs on that plot,<br>Then the incident is logged in the dashboard but external push/SMS notifications are suppressed. | EP06 |
| US25 | Configure Localized Control Schedules | As an Agricultural Producer, I want to define automated time windows for localized pest control actions so that interventions only run during optimal field hours. | **Scenario: Trigger actuation within allowed window**<br><br>Given a confirmed target pest request occurs inside the permitted schedule (e.g., nighttime),<br>When the approval flow executes,<br>Then the actuation command is dispatched to the Edge controller.<br><br>**Scenario: Block actuation outside allowed window**<br><br>Given a control request is approved outside the configured hours,<br>When the actuation manager checks the schedule,<br>Then the command is held or rejected with a schedule safety violation log. | EP05 |
| US26 | View System Health and Edge Gateway Status | As an Agricultural Producer, I want to view the connectivity, battery, and storage status of my Edge gateways so that I can address hardware issues before monitoring is interrupted. | **Scenario: Gateway is healthy and communicating**<br><br>Given the Edge gateway sends periodic heartbeats,<br>When the producer checks the hardware status dashboard,<br>Then the platform displays green status indicators for CPU, battery voltage, signal strength, and pending sync queue.<br><br>**Scenario: Gateway loses communication**<br><br>Given no heartbeat has been received beyond the threshold,<br>When the health monitor checks device statuses,<br>Then the platform flags the gateway as "Offline" and alerts the producer. | EP03 |
| US27 | Configure Manual Override Emergency Lockout | As an Agricultural Producer, I want to manually trigger an emergency physical lockout for all actuators so that field operators can safely work on maintenance without software interference. | **Scenario: Activate manual lockout**<br><br>Given a field operator initiates maintenance,<br>When the operator triggers the "Emergency Lockout" switch in the app,<br>Then all physical actuators on the plot are disabled and reject any incoming actuation commands.<br><br>**Scenario: Clear manual lockout**<br><br>Given the maintenance is completed,<br>When the authorized operator clears the lockout with a confirmation code,<br>Then normal automated and manual control flows are restored. | EP04 |
| US28 | Set Up Custom Water Consumption Baselines | As an Agricultural Producer, I want to set custom seasonal water volume baselines per crop phase so that flow anomaly logic adapts to varying irrigation needs. | **Scenario: Activate seasonal baseline**<br><br>Given the crop enters a new growth phase,<br>When the producer updates the expected flow rate baseline,<br>Then the anomaly detection engine scales its thresholds relative to the new expected volume. | EP03 |
| US29 | Review AI Model Accuracy and False Positive Metrics | As an Agricultural Producer, I want to view a monthly model accuracy summary based on human validations so that I can evaluate AI reliability over time. | **Scenario: Display accuracy metrics**<br><br>Given human validations have been submitted for past inferences,<br>When the producer views the model health dashboard,<br>Then the platform calculates and displays precision, recall, and false-positive rates per target pest. | EP07 |
| US30 | Manage Offline Telemetry Storage Limits | As an Agricultural Producer, I want the Edge gateway to manage local disk usage during prolonged offline periods so that critical evidence is preserved over raw telemetry. | **Scenario: Purge low-priority cache under high storage usage**<br><br>Given the Edge gateway storage reaches 90% capacity while offline,<br>When new images or readings arrive,<br>Then the local engine purges old raw telemetry records first while retaining confirmed anomaly events and evidence images. | EP03 |
| TS01 | Receive Device Telemetry through the Edge API | As a Developer, I want the Edge API to receive authenticated telemetry so that each record has a trusted device, timestamp, and source. | **Scenario: Receive a valid payload**<br><br>Given a registered device sends a supported payload with valid credentials,<br>When the Edge API validates it,<br>Then the record is stored in SQLite and acknowledged with its local identifier.<br><br>**Scenario: Reject an invalid payload**<br><br>Given required fields or credentials are invalid,<br>When the payload reaches the Edge API,<br>Then the API rejects it and records a security or validation event without storing it as valid telemetry. | EP08 |
| TS02 | Run Pest Inference at the Edge | As a Developer, I want the gateway to run the versioned pest model locally so that detections can continue without Internet connectivity. | **Scenario: Process a supported image**<br><br>Given an authorized camera provides a valid image,<br>When the inference worker processes it,<br>Then it stores class, confidence, count, regions, model version, and processing time.<br><br>**Scenario: Fail to process an image**<br><br>Given the image is corrupt or the model cannot run,<br>When processing fails,<br>Then the worker records the failure, creates no pest confirmation, and preserves diagnostic metadata. | EP08 |
| TS03 | Enforce Actuator Safety Interlocks | As a Developer, I want all actuator commands to pass local safety checks so that cloud errors or duplicated messages cannot cause unsafe repetition. | **Scenario: Accept a valid idempotent command**<br><br>Given the command is signed, current, unique, and within limits,<br>When the Edge controller validates it,<br>Then it executes the action once and stores the command identifier.<br><br>**Scenario: Receive a duplicated or expired command**<br><br>Given the command identifier was processed or its expiry time passed,<br>When the controller receives it,<br>Then it rejects the command and keeps the actuator state unchanged. | EP08 |
| TS04 | Synchronize Pending Edge Records | As a Developer, I want the Edge API to synchronize pending records with the Cloud REST API so that temporary Internet interruptions do not erase monitoring history. | **Scenario: Synchronize after connectivity returns**<br><br>Given pending records exist and Internet connectivity returns,<br>When synchronization runs,<br>Then records are sent in order and marked as synchronized after confirmation.<br><br>**Scenario: Retry without duplicates**<br><br>Given a previous request timed out after reaching the Cloud API,<br>When the Edge retries the same batch,<br>Then the Cloud API uses idempotency keys and creates no duplicates. | EP08 |
| TS05 | Upload Evidence Images Securely | As a Developer, I want to upload evidence images with integrity metadata so that every inference remains traceable to its source. | **Scenario: Upload a valid image**<br><br>Given a supported image and metadata are available,<br>When the Edge API synchronizes them,<br>Then the Cloud stores the object reference, checksum, observation point, capture time, and model result.<br><br>**Scenario: Reject an unsupported image**<br><br>Given the format or size is unsupported,<br>When upload is attempted,<br>Then the API rejects it and preserves the local record for diagnosis. | EP08 |
| TS06 | Preserve an Auditable Action Log | As a Developer, I want commands, approvals, device feedback, and failures to be immutable audit records so that every physical action can be reconstructed. | **Scenario: Record a completed action**<br><br>Given an actuator action starts and stops,<br>When Edge feedback is synchronized,<br>Then the Cloud stores command, authorizer, timestamps, device, requested duration, actual duration, and result.<br><br>**Scenario: Prevent direct history replacement**<br><br>Given an authenticated user edits a current configuration,<br>When the change is saved,<br>Then historical action records remain unchanged and a new configuration version is created. | EP08 |
| TS07 | Implement Fallback and Circuit Breakers for Cloud REST Services | As a Developer, I want to implement circuit breakers on the Edge API so that Cloud API slowdowns or outages do not cause local buffer overflows or gateway crashes. | **Scenario: Trip circuit breaker on repeated Cloud timeouts**<br><br>Given the Cloud REST API returns 5xx errors or times out repeatedly,<br>When the failure threshold is reached,<br>Then the Edge API trips the circuit breaker, shifts exclusively to local SQLite storage, and pauses cloud sync retries for a cooldown period.<br><br>**Scenario: Reset circuit breaker after recovery**<br><br>Given the cooldown period expires and health checks pass,<br>When the circuit breaker enters the half-open state,<br>Then it sends a test batch and resumes normal synchronization upon confirmation. | EP08 |
| TS08 | Implement Automated Database Migration and Versioning at the Edge | As a Developer, I want to run automated database migrations on local SQLite databases so that Edge devices update their schemas seamlessly during firmware upgrades. | **Scenario: Execute pending migrations on startup**<br><br>Given a new firmware version with schema changes is deployed to the Edge gateway,<br>When the local service initializes,<br>Then it applies pending SQL migrations in transactional sequence without corrupting un-synchronized telemetry.<br><br>**Scenario: Rollback migration on error**<br><br>Given a migration script encounters a syntax or constraint failure,<br>When the migration runner detects the error,<br>Then it rolls back the transaction, restores the previous DB snapshot, and logs a critical diagnostic event. | EP08 |
| TS09 | Secure Edge-to-Cloud Communication with Mutual TLS (mTLS) | As a Developer, I want to enforce Mutual TLS (mTLS) authentication between Edge gateways and the Cloud REST API so that unauthorized hardware cannot push false telemetry or read field data. | **Scenario: Authenticate with a valid client certificate**<br><br>Given an Edge gateway connects using a valid, unexpired device certificate signed by the AgroLeak CA,<br>When the Cloud API handshake completes,<br>Then the TLS connection is established and requests are processed.<br><br>**Scenario: Reject connection with an untrusted or revoked certificate**<br><br>Given a device attempts connection with an invalid or revoked certificate,<br>When the Cloud gateway inspects the TLS handshake,<br>Then the connection is terminated immediately at the network boundary. | EP08 |
| TS10 | Process Inference Queue Asynchronously at the Edge | As a Developer, I want to decouple image capture from inference processing using an in-memory queue so that high capture rates do not block camera ingestion or telemetry tasks. | **Scenario: Enqueue image and process asynchronously**<br><br>Given a camera captures a new frame,<br>When the frame is added to the local processing queue,<br>Then the camera thread releases immediately while the background inference worker picks up the frame for AI processing.<br><br>**Scenario: Queue overflow drop policy**<br><br>Given the processing queue reaches its maximum capacity,<br>When a new frame arrives,<br>Then the worker drops the oldest non-essential frame, records a queue drop metric, and preserves system stability. | EP08 |
